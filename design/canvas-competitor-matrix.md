## ④ 差异卖点核对：「审批门+队列治理全场空白」验证结果

逐家核对（依据=调研原文证据指针）：

| 竞品 | 审批门 | 队列/任务治理 | 判定 |
|---|---|---|---|
| dsh-image-gen | 无（三核心文件 grep approval/confirm/consent 零命中，单品报告 :46） | 无持久队列（#99 根因分析实证：useState、切页即丢、已计费无结果） | 空白成立，且其痛点（切页即丢/已计费无结果）是我方获客话术 |
| tigerowo | 无；仅默认关闭的「Agent 自动提交」开关（降级形态） | **有**：任务持久化+后端轮询+停止重试+AI 日志 | 队列治理不空白；审批门仅降级形态且默认关 |
| hero8152 | 无 | 仅排队位置显示，全仓无并发闸/审批门/配额 | 空白成立（但已停更） |
| dsh-agnes-media | 调研未提及 | **有且强**：宿主托管/断点续跑/失败隔离/重启恢复/退避重试 | 队列治理不空白——它正是我方 P1 #4 对标来源 |
| dsh-ark9canvas | **有**：默认阻塞等人工批准、拒绝/超时零计费（commit 90abdd7） | 批量 1-10 子任务聚合；持久队列无证据 | **「审批门全场空白」被它推翻**——但已停滞 2 个月、零 issue/PR，且它本就是我方 P0 #3 的来源（ROADMAP 自注「dsh-ark9canvas 杀手锏」） |
| toonflow | 调研未提及 | 调研未提及 | 未见（调研未覆盖，不推定为无，需补查） |
| stablediffusion-infinity | 调研未提及 | 调研未提及 | 未核实（治理面未被调查，PoC 定位，不推定为无） |

| jsoncanvas/引擎 | 不适用 | 不适用 | 不适用（标准/引擎，非产品） |
| 商业三家 | 未见 | 未见；TapNow Enterprise 有共享 credits+中央用量（商业侧形态） | 商业平台靠积分天然限流；坤肉「生成前积分预估」是轻量把关的商业形态，非人工审批门 |
| linux.do 信号 | 未提及 | 用户诉求「多任务并发不互卡」（2413743#2）；basketikun 已有任务并发显示，审批门未见 | 需求侧印证并发是刚需；结合上表，三合一（审批门+队列治理+画布入口）仍无一家被实证同时具备 |

**结论：预设部分推翻、核心主张仍成立但须收窄措辞。**
1. 「审批门全场空白」**不成立**：dsh-ark9canvas 有默认审批门（且是我方 P0 #3 的直接来源），坤肉有积分预估轻量形态，tigerowo 有降级开关。准确说法是：**现有调研证据范围内，活跃迭代的竞品中未见把审批门做成默认治理者**（ark9 有但停滞 2 个月；agnes-media/toonflow/stablediffusion-infinity 审批面未核实，不推定为无）。
2. 「队列治理全场空白」**不成立**：agnes-media 与 tigerowo 都有实质任务治理实现。
3. **仍然独占的是三合一（以现有调研证据为界）**：「审批门+队列治理+画布生成入口」无一家被实证同时具备——image-gen 有画布无治理（grep 零命中+#99）；tigerowo 有任务治理、其报告 :40 实证无逐任务审批队列；ark9 有审批门无画布且停滞；agnes-media 有任务治理但审批门仅「调研未提及」（未核实、不推定为无），且画布偏媒体工作流；toonflow/商业三家未见。我方 README 已把三者装进同一插件（队列页审批区+并发闸+无限画布）。宣传措辞建议从「全场空白」改为「**三合一治理的生图画布，活跃竞品中独此一家**」，并用 image-gen 的 #99 痛点（切页即丢、已计费无结果）做获客话术。
4. 待补：toonflow 的审批/队列面与 agnes-media 的审批面调研未覆盖（后者仅「未提及」），下轮补查后再定稿对外话术。
